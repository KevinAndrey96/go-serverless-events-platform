# ADR-0003: Compile-Time Dependency Injection using Google Wire

## Status
`Accepted`

## Context
AWS Lambda functions are ephemeral execution environments subject to cold starts. Traditional dependency injection (DI) frameworks in Go (such as Uber's `fx` or reflection-based containers) perform runtime dependency resolution, service graph traversal, and reflection inspection on every microservice startup.

In high-concurrency event-driven scenarios, cold start latency directly impacts API Gateway response times, degrading user experience during ticket drop spikes.

## Decision
We enforce **Compile-Time Dependency Injection using Google Wire** (`github.com/google/wire`) across all Go Lambda microservices (`create`, `show`, `change_status`, `change_pay_status`, `event-users`, `reminder`).

Wire generates explicit, standard Go code during compilation (`wire_gen.go`), completely eliminating runtime reflection, dynamic lookups, and graph validation overhead during Lambda cold initialization.

### Injection Structure:
```
backend/pkg/infrastructure/
  ├── aws/dynamodb.go      # DynamoDB Client Provider
  └── email/smtp.go        # SMTP Transport Provider
backend/create/v1/
  ├── wire.go              # Injector Specification
  ├── wire_gen.go          # Autogenerated Static Graph
  └── main.go              # Lambda Entrypoint
```

## Consequences
- **Positive:**
  - **Sub-50ms Cold Starts:** Initialization executes plain Go struct instantiations without reflection penalty.
  - **Compile-Time Safety:** Missing dependencies, circular references, or mismatched provider signatures fail immediately during `go build`, preventing runtime panics in production.
  - **Clean Testability:** Interfaces can be seamlessly swapped with mock implementations (`pkg/mock`) in unit test suites without requiring special DI harnesses.
- **Negative:**
  - Developers must run `wire ./...` whenever service provider constructor signatures change.
